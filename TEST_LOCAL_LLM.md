# Проверка локальной модели Qwen3-4B

26 ноября 2026 года. Ветка `student`.

## Исходная конфигурация

- Ollama `0.13.5` в отдельном контейнере Docker Compose. Локальный адрес `http://127.0.0.1:11435`.
- Модель `qwen3:4b`, GGUF, квантизация `Q4_K_M`. Идентификатор модели `359d7dd4bcdab3d86b87d73ac27966f4dbb9f5efdfcc75d34a8764a09474fae7`.
- Python-скрипт запускался на хосте. Ollama использовала существующий том `enterprise-private-gpt_ollama_models` из проекта Enterprise Private GPT, подключённый только для чтения.
- Выполнение на CPU. Контекст 4 096 токенов, лимит ответа 200 токенов, `temperature: 0`, `seed: 42`, `think: false`.
- Три последовательных потоковых запроса к `/api/chat`. Время до первого фрагмента измерено на клиенте с начала запроса до первого непустого `message.content`.

## Сценарий

Бриф для VK — сезонный сливочный раф московской кофейни «Зерно». Аудитория — местные жители 25–40 лет. Тон живой и спокойный. Цены и адреса придумывать нельзя. Призыв — зайти на чашку рафа.

1. Копирайтер получил бриф. Перед вызовом модель отсутствовала в списке загруженных моделей Ollama.
2. Копирайтер повторно получил тот же запрос и вернул тот же текст.
3. Редактор получил исходный бриф и черновик и вернул решение и замечание.

В этом прогоне проверены два агента через API Ollama. Сквозной граф и запись в Langfuse предстоит проверить отдельно.

Проверка SHA-256 подтвердила, что скрипт в контейнере совпадает с файлом проекта. Версия Ollama, идентификатор и квантизация модели, бриф и параметры генерации совпали с исходным прогоном.

### Сравнение с исходным прогоном

- **Ответы и токены совпали.** Копирайтер вернул тот же текст, а редактор повторил одобрение с замечанием о тоне. Каждый прогон израсходовал 464 входных и 247 выходных токенов. Все ответы прошли проверку структуры JSON и завершились с `done_reason: stop`. Счётчик кешированных токенов отсутствовал во всех ответах.
- **Задержки различались.** Сумма времени трёх запросов на клиенте составила 102,19 с в исходном прогоне, 84,19 с в первом контейнерном прогоне и 83,24 с во втором. В первом контейнерном прогоне холодный запрос занял 30,17 с, а в исходном холодном прогоне — 36,32 с. Эти единичные замеры показывают разброс задержек. Чтобы оценить вклад контейнеризации в скорость, нужны серии повторов при одинаковом состоянии модели и сопоставимой нагрузке на CPU.

Контейнеризация воспроизвела ответы модели, расход токенов и набор доступных метрик. Проверка охватывает Ollama и Python-скрипт. Сквозной граф агентов и запись в Langfuse предстоит проверить отдельно.

## Правило для графа

1. **Принято.** Текст соответствует всем критериям. Редактор возвращает только решение об одобрении. Граф передаёт текст `Publisher`.
2. **Не принято.** Нарушен хотя бы один критерий. Редактор возвращает решение об отклонении и одну или несколько конкретных обязательных правок. Граф возвращает черновик `Copywriter` на доработку.

Схема ответа допускает только эти две формы. Ответ с одобрением и замечаниями считается недействительным и не пропускает текст к `Publisher`. Выявленное в тесте несоответствие тону по этому правилу требует отклонения с обязательной правкой.

## Повторение теста

Запустите команды из корня проекта. Текущая конфигурация Compose загружает модель в собственный том проекта при первом запуске.

```sh
docker compose up --build -d --wait --wait-timeout 900
docker compose exec -T python python scripts/check_ollama.py --url http://ollama:11434
```

Для холодного замера модель перед первым запросом должна отсутствовать в списке загруженных моделей. Скрипт записывает это в `model_loaded_before_first_call`.
